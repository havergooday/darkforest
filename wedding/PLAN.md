# 모바일 청첩장 이스터에그 — 해킹 터미널 미니게임

기존 모바일 청첩장에 숨은 트리거를 하나 심고, 그걸 누르면 **별도 URL의 터미널 화면**으로
넘어간다. 초록 글씨가 주르륵 흐르며 "결혼 정보가 유출되는 중"이라고 협박하고,
하객이 축하 메시지를 입력하면 침입이 막히면서 아스키 청첩장이 뜬다.

**모청 본체는 건드리지 않는다.** 손대는 건 숨은 링크 한 줄뿐이고, 나머지는 전부
이 저장소의 단일 HTML 파일 안에서 끝난다. 빌드·의존성·서버 없음 — 저장소의 기존 방식 그대로.

---

## 1. 컨셉 한 줄

> 청첩장을 해킹당했다. 막을 방법은 축하하는 것뿐이다.

협박 → 저항 → 축하. 이 반전 하나가 전부다. 나머지 연출은 이 반전을 위한 준비다.

---

## 2. 전체 흐름

```
[기존 모청]  숨은 트리거(로고 5연타 / 날짜 길게 누르기)
      │
      ▼
hack.html?k=코드      ← 새로 만드는 것. 여기부터 전부 우리 영역
      │
  ┌───┴───────────────────────────────────────────┐
  │ 0. 암전      검은 화면, 커서만 깜빡            │  탭 대기
  │ 1. 침입      부팅 로그가 주르륵 흐른다          │  ~8초 (스킵 가능)
  │ 2. 협박      유출 게이지가 차오른다             │  ~4초
  │ 3. 저항      미션 2개 — 성공할 때마다 조각 복구  │  하객 페이스
  │ 4. 해제      두 사람이 만나고 하트가 피어난다    │  머무는 화면
  └───────────────────────────────────────────────┘
      │
      ▼
[모청으로 돌아가기]   항상 떠 있는 탈출구
```

핵심은 **3번에서만 시간을 쓰게 하는 것**이다. 1·2번 연출이 길면 하객은 그냥 닫는다.
연출 총량 12초를 넘기지 않고, 첫 탭부터 스킵 버튼이 우상단에 계속 떠 있다.

---

## 3. 화면별 설계

### 0. 암전 — 진입 게이트

모바일은 사용자 제스처 없이 소리를 못 낸다. 그래서 "탭해서 접속" 화면이 기술적으로 필요한데,
이걸 연출로 쓴다. 검은 화면에 커서 하나만 깜빡이고 그 아래 흐린 글씨.

```
> _

        [ 화면을 누르십시오 ]
```

비밀코드를 쓴다면 여기서 받는다. 단 **입력은 선택**이다 —
URL에 `?k=` 가 이미 있으면 통과, 없으면 코드 입력창. 어르신 하객이 코드에서 막히면
그걸로 끝이므로, 3초 뒤 힌트가 흐리게 떠오르고 아무거나 쳐도 결국 통과시킨다.

### 1. 침입 — 주르륵 흐르는 로그

가짜 부팅 로그. 진짜처럼 보이되 **읽으면 웃긴** 내용이어야 한다. 그래야 스크롤을
끝까지 본다.

```
$ ssh guest@wedding.invite
Connecting to 192.168.10.10 ... OK
[  0.001 ] mounting /heart ................ done
[  0.014 ] scanning couple_records ........ 2 found
[  0.220 ] decrypting VOW.dat ............. ████████░░ 82%
[  0.981 ] WARNING: unauthorized access detected
```

- 줄마다 지연을 다르게 준다 (40~400ms 랜덤). 일정하면 가짜 티가 난다
- 중간에 `████░░░░` 프로그레스가 제자리에서 차오르는 줄을 두 개쯤 섞는다
- 마지막 줄에서 색이 초록 → 빨강으로 넘어가며 화면이 한 번 흔들린다

### 2. 협박 — 유출 게이지

```
!! WEDDING DATA BREACH !!

  신랑 이름   ▓▓▓▓▓▓▓▓▓▓  유출됨
  신부 이름   ▓▓▓▓▓▓▓▓▓▓  유출됨
  예식 일시   ▓▓▓▓▓▒░░░░  유출 중...
  예식 장소   ░░░░░░░░░░  대기

  차단하려면 인증이 필요합니다.
  > 축하 메시지를 입력하십시오
```

여기서 처음으로 **하객이 뭘 해야 하는지**가 명확해진다. 그 전까지는 구경만 한다.

### 3. 저항 — 미션 2개

| # | 미션 | 입력 방식 | 복구되는 것 |
|---|---|---|---|
| M1 | 축하 메시지 입력 | 키보드 (1회뿐) | 신랑·신부 이름 |
| M2 | 하트 연타로 심박 맞추기 | 탭 연타 | 예식 일시·장소 |

**키보드는 M1에서 딱 한 번만 쓴다.** 모바일에서 키보드가 올라오면 화면 절반이 사라진다.
그 상태를 반복시키면 짜증난다. M2는 손가락만으로 끝난다.

미션을 둘로 줄인 만큼, 남은 무게는 전부 마지막 화면으로 옮겼다. 관문이 길어질수록
하객은 닫는다 — 재미는 통과한 뒤에 있어야 한다.

- **M1 판정은 아주 관대하게.** `축하`·`ㅊㅋ`·`행복`·`♥`·`congrat`·`ㅋㅋ` 전부 통과.
  2회 틀리면 "힌트: 축, 하" 가 뜨고, 3회째는 뭘 쳐도 통과시킨다. 여기서 막히면 안 된다
- **M2**는 15탭 × 3초 제한. 두드릴 때마다 하트가 떠오르고 심박 파형 `_/\_/\_/\` 이 자란다.
  실패해도 "그래도 마음은 전해졌습니다" 로 통과

즉 **실패로 끝나는 경로는 없다.** 청첩장이지 게임이 아니다. 난이도는 연출일 뿐이다.

### 4. 해제 — 아스키 청첩장

빨강이 걷히고 초록이 돌아온다. 여기가 이 페이지에서 제일 오래 머무는 화면이므로,
정적인 액자로 끝내지 않고 **순서대로 벌어지는 장면**으로 만든다.

```
1  액자 위 테두리가 그려지고  ACCESS GRANTED
2  빈 줄 여덟 개를 미리 잡아 둔다        ← 하트가 피어날 자리
3  두 사람이 양 끝에서 걸어 들어온다      ← 2.3초
4  가운데서 만나 <3 이 뜨고 반짝인다
5  그 자리에서 하트가 아래→위로 피어난다  ← 동시에 하트 비 시작
6  이름 · 일시 · 장소가 한 줄씩 찍힌다
```

완성된 모습:

```
+======================================+
|     A C C E S S   G R A N T E D      |
|              ###   ###               |
|             ##### #####              |
|             ###########              |
|              #########               |
|               #######                |
|                #####                 |
|                 ###                  |
|                  #                   |
|                 \  /                 |
|               o     (o)              |
|              /|\ <3 /|\              |
|              / \    /_\              |
|            W E D D I N G             |
|                홍길동                 |
|                 and                  |
|                성춘향                 |
|       2026년 10월 10일 토요일         |
|            오후 1시 30분              |
|               OO컨벤션                |
|             3층 그랜드홀              |
+======================================+
```

**걸어 다니는 두 사람은 스프라이트가 아니라 글자판이다.** 액자 안이므로 폭 38칸의
문자 배열에 직접 찍고, 그 배열을 네 줄에 뿌린다. `position:absolute` 로 캐릭터를
띄우면 줄 높이가 흐트러지지만, 글자판은 액자와 같은 격자를 쓰므로 어긋날 수 없다.

- 걸을 때 다리가 `/ \` ↔ `| |` 로 바뀌고, 신부는 팔을 `/|\` ↔ `\|/` 로 흔든다
- 만난 뒤에도 가만히 있지 않는다 — 640ms마다 몸을 흔들고 머리 위 반짝임이 `\  /` ↔ `/  \`
- 사이를 네 칸 비워 하트가 양쪽에 달라붙지 않게 했다

**하트 비**는 캔버스가 아니라 글자다. `♥ ♡ ·` 26방울이 각자 다른 속도·크기·투명도로
떨어지고, `transform` 만 움직이므로 저사양 폰에서도 부담이 없다. 글자 뒤(z-index 1)에
깔려 읽는 것을 방해하지 않는다.

액자 안의 **한글은 아스키 아트로 그리지 않는다.** 별도 DOM 줄로 중앙정렬해서 얹는다.
(이유는 6장 함정 참고)

액자 아래에 실제 기능 버튼:

- `[ 오시는 길 ]` — 기존 모청의 지도 링크 그대로 재사용
- `[ 청첩장으로 돌아가기 ]` — 항상 최상단 우선순위
- `[ 다시 해킹당하기 ]` — 한 번 더 보고 싶은 사람용

## 4. 데이터 구조

파일 맨 위 상수 블록 하나에 전부 모은다. 나중에 실제 정보로 바꿀 때
**이 블록만 고치면 되도록** 한다. 지금은 전부 자리표시자다.

```js
const INVITE = {
  groom:  { name: '홍길동', parents: '홍아버지 · 홍어머니' },
  bride:  { name: '성춘향', parents: '성아버지 · 성어머니' },
  date:   '2026-10-10T13:30',      // 표시는 코드가 만든다
  place:  { name: 'OO컨벤션', hall: '3층 그랜드홀', mapUrl: '' },
  back:   '',                       // 기존 모청 URL ← 반드시 채울 것
  code:   'LOVE',                   // 비밀코드 (대소문자 무시)
};
```

연출 스크립트(로그 대사)도 코드가 아니라 배열 데이터로 뺀다.
대사를 고치려고 로직을 읽을 일이 없어야 한다.

```js
const BOOT = [
  ['$ ssh guest@wedding.invite', 30],
  ['Connecting to 192.168.10.10 ... OK', 220],
  ...
];
```

## 5. 모바일 세로 대응

이 페이지는 **세로 화면이 기본값이고 가로는 고려하지 않는다.** 청첩장은 세로로 본다.

| 항목 | 처리 |
|---|---|
| 화면 높이 | `100dvh` (`100vh` 아님 — 주소창 때문에 잘린다) |
| 노치·홈바 | `viewport-fit=cover` + `env(safe-area-inset-*)` 패딩 |
| 키보드 | `visualViewport` 리사이즈를 듣고 입력줄을 키보드 바로 위에 고정 |
| 글자 크기 | 본문 13px, 최소 12px. `-webkit-text-size-adjust:100%` 로 자동확대 차단 |
| 아스키 폭 | **38칸 이내로 설계.** 그래도 넘치면 컨테이너를 `transform:scale()` 로 축소 |
| 로그 스크롤 | 새 줄이 붙을 때마다 하단 고정. 단 하객이 위로 스크롤하면 자동추적 해제 |
| 확대/스크롤 | 게임 영역은 `touch-action:manipulation`, 더블탭 확대 차단 |

타이핑은 `setInterval` 이 아니라 `requestAnimationFrame` + 경과시간 누적으로 돌린다.
백그라운드 탭이나 저사양 폰에서 타이머가 밀리면 연출이 통째로 어긋난다.

`prefers-reduced-motion` 이 켜져 있으면 흔들림·글리치를 끄고 타이핑을 즉시 완료로
바꾼다. 소리는 **기본 꺼짐** — 지하철에서 여는 하객이 반드시 있다. 우상단에 `♪` 토글만 둔다.

## 6. 미리 알아 둘 함정

**한글과 박스문자는 폭이 어긋난다.** 모노스페이스라도 한글은 영문 2배 폭이고,
`─│┌┐` 같은 박스 드로잉 문자는 폰트마다 1배·2배가 갈린다. 액자가 삐뚤어지는 원인이
대부분 이것이다. → **액자는 순수 ASCII(`+ - | =`)로만 그리고, 한글은 액자 위에 얹는다.**

**폰트 폴백.** iOS·안드로이드에 D2Coding이 없다. `ui-monospace, SFMono-Regular,
Menlo, Consolas, monospace` 로 잡되, 한글 모노스페이스는 결국 시스템 고딕으로 떨어진다.
그래서 위 규칙이 더 중요하다.

**뒤로가기.** 하객은 브라우저 뒤로가기로 나간다. 미션 중간 상태를 히스토리에 쌓지 않는다.

**재방문.** 클리어 기록을 `localStorage` 에 남기고, 두 번째 방문부터는
"다시 볼까요? / 청첩장으로" 를 먼저 묻는다. 두 번째에 연출을 다시 8초 보는 건 고문이다.

**카카오톡 인앱 브라우저.** 청첩장 링크는 십중팔구 카톡에서 열린다.
인앱 브라우저는 `dvh` 지원과 키보드 처리가 표준과 다르다. **실기기 테스트 필수.**

## 7. 모청 쪽에 심는 트리거

기존 청첩장에서 고칠 부분은 이것뿐이다.

```html
<!-- 예: 상단 이름 영역을 5번 연타하면 열린다 -->
<script>
(() => {
  let n = 0, t = 0;
  document.querySelector('#names').addEventListener('click', () => {
    const now = Date.now();
    n = (now - t < 800) ? n + 1 : 1;
    t = now;
    if (n >= 5) location.href = 'hack.html?k=LOVE';
  });
})();
</script>
```

트리거 후보 — 눌러 볼 만하되 실수로 눌리진 않는 자리:

- 이름 5연타 (위 예시, 추천)
- 예식 날짜를 1.5초 길게 누르기
- 갤러리 마지막 사진 한 장을 더 넘기려 할 때

## 8. 작업 단계

| 단계 | 내용 | 끝났다고 말할 수 있는 기준 | 상태 |
|---|---|---|---|
| S1 | 파일 뼈대 + 타이핑 엔진 + 스킵 | 로그가 흐르고 아무 때나 스킵된다 | 완료 |
| S2 | 연출 스크립트 데이터화 (0~2단계) | 대사를 배열에서만 고칠 수 있다 | 완료 |
| S3 | 미션 2종 + 실패 없는 통과 로직 | 일부러 다 틀려도 4단계에 도달한다 | 완료 |
| S4 | 아스키 청첩장 + 걷는 장면 + 하트 비 | 액자가 안 깨지고 링크가 살아 있다 | 완료 |
| S5 | 모바일 마감 (키보드·safe-area·reduced-motion·재방문) | 키보드가 올라와도 입력줄이 보인다 | 완료 |
| S6 | 실기기 확인 (iOS Safari, 안드로이드 크롬, **카톡 인앱**) | 세 환경에서 처음부터 끝까지 완주 | **남음** |

S1~S5는 `wedding/test.js` 가 자동으로 검사한다. **S6만은 진짜 폰이 필요하다** —
카톡 인앱 브라우저의 `dvh`·키보드 동작은 코드로 흉내 낼 수 없다.

## 9. 산출물과 확인 방법

```
wedding/
  PLAN.md      ← 이 문서
  hack.html    ← 미니게임 본체. 단일 파일, 의존성 없음
  test.js      ← 흐름 검사
```

```sh
node wedding/test.js                          # 흐름 검사
python -m http.server 8765 --bind 127.0.0.1   # 눈으로 보기
```

검사는 저장소의 `test/harness.js` 와 같은 방식이다. `hack.html` 의 `<script>` 블록을
그대로 꺼내 `vm` 에서 돌리므로 **항상 실제로 배포되는 파일을 검증한다.** 사본을 두지 않는다.

특히 눈으로는 놓치기 쉬운 것들을 잡는다 — 액자 위아래 테두리 길이가 어긋나는 것,
하트 줄마다 폭이 달라 통째로 기우는 것, 건너뛰기를 눌렀는데 지워진 연출이 뒤늦게
화면에 끼어드는 것, 미션 중의 탭이 빨리감기로 먹혀 미션이 통째로 날아가는 것.

- 미니게임: http://127.0.0.1:8765/wedding/hack.html
- 코드 없이 바로: http://127.0.0.1:8765/wedding/hack.html?k=LOVE
- 청첩장만 보기: http://127.0.0.1:8765/wedding/hack.html?skip=1
- 재방문 안내 무시: `&force=1`

브라우저 콘솔에서 `hack.end()` / `hack.reset()` / `hack.state()`.

같은 네트워크의 폰으로 볼 때는 `--bind 0.0.0.0` 으로 띄우고 PC의 사설 IP로 접속한다.

## 10. 아직 안 정한 것

- **실제 예식 정보** — 지금은 전부 자리표시자다. `INVITE` 블록만 채우면 된다
- **비밀코드를 실제로 받을지** — 그냥 URL로 바로 열어도 되고, 코드를 청첩장 어딘가에
  숨겨 두는 재미를 줄 수도 있다. 코드를 쓴다면 어디에 숨길지도 같이 정해야 한다
- **걷는 캐릭터를 두 사람답게 손볼지** — 지금은 신랑 `/ \`, 신부는 드레스 `/_\` 와
  면사포 `(o)` 로만 구분한다. 안경이나 부케 같은 것을 한 글자로 더 넣을 수 있다
- **부모님 성함·계좌 노출 범위** — 이 저장소가 공개라면, 실제 정보를 넣는 시점에
  비공개 저장소나 별도 호스팅으로 옮길지 먼저 정한다
- **소리** — 타자기·발소리·성공음은 WebAudio 로 만들어 넣었다(파일 없음, 기본 꺼짐).
  더 살릴지 아예 뺄지는 실기기에서 들어 보고 정한다
