# 숲 (darkforest)

숲 한가운데서 눈을 뜬다. 가진 건 아무것도 없다.
불을 피우고, 자원을 모으고, 도구를 만들며 며칠을 버틴다.

**▶ [플레이](https://havergooday.github.io/darkforest/)**

브라우저에서 도는 텍스트 서바이벌. 단일 HTML 파일이고 빌드·의존성·서버가 없다.
진행 상황은 브라우저 `localStorage`에 자동 저장된다.

## 핵심 루프

```
탐색 → 채집 → 거점 복귀 → 제작 → 더 멀리 탐색
                  ↑
              불 / 체온 회복
```

행동 하나가 1턴. 턴이 지나면 허기와 체온이 깎이고, 거점의 불 옆에서만 체온이 회복된다.

- **허기**는 생존, **체온**은 능력 — 역할이 겹치지 않는다. 어느 쪽을 먼저 해결할지 매 순간 고른다
- 거점에서 멀수록 체온이 빨리 깎이고, 대신 칸의 자원 잔량이 많다
- 칸은 다 캐면 마른다. 소지 한도가 있으니 여러 칸을 돌아야 한다
- 열매로는 못 버틴다. 도구를 만들어 사냥으로 넘어가야 살아남는다

## 조작

- **이동** — 지도에서 인접한 칸 클릭, 또는 방향키 / `WASD`
- **행동** — 오른쪽 목록에서 선택
- 지도 아래 범례와 로그가 현재 상황을 알려준다

## 로컬에서 열기

```sh
python -m http.server 8765 --bind 127.0.0.1
# http://127.0.0.1:8765/
```

`file://`로 직접 열어도 돌아가지만, 브라우저마다 `file://` origin의 `localStorage` 취급이
달라 저장·불러오기 동작이 어긋날 수 있다.

## 개발용 콘솔

브라우저 콘솔(F12)에서 `game.help()`

```js
game.s                       // 상태 전체
game.skip(20)                // 20턴 넘기기
game.give('stone', 20)       // 자원 지급
game.all()                   // 자원 + 제작대 2단계
game.tool()                  // 도구 전부 해금
game.keep()                  // 소지품 전부 획득
game.reveal()                // 지도 공개
game.tune({TEMP_FIRE: 20})   // 새로고침 없이 밸런싱 값 변경
game.reset()                 // 새로 시작
```

밸런싱 수치는 `index.html` 상단 `CONFIG` 블록에 모여 있다.

## 테스트

```sh
node test/all.js
```

Node만 있으면 된다. 게임 자체에는 의존성이 없고, 테스트도 외부 패키지를 쓰지 않는다.

`index.html`의 `<script>` 블록을 그대로 꺼내 `vm` 컨텍스트에서 돌리고, `document`와
`localStorage`만 최소 스텁으로 채운다. 미리 추출한 사본을 두지 않으므로 **항상 실제로
배포되는 파일을 검증한다.**

| 스위트 | 검증 대상 |
|---|---|
| `test/bugfix.test.js` | 재료 검사, 빈 칸 채집, 세이브 스키마 복원 |
| `test/loot.test.js` | 야영지 발견물, 소지 한도 부분 획득, 잔존·재방문 |
| `test/keep.test.js` | 소지품 가방, 구버전 세이브 이관, 확장성 |

주로 **조용히 상태를 깨뜨리는 종류**를 잡는다 — 재료 없이 제작대가 세워져 가방 수량이
음수가 되는 것처럼, 화면상으로는 정상이라 눈으로는 알 수 없는 버그다.

## 실험

### 던전 (위저드리식)

[`experiment/dungeon.html`](experiment/dungeon.html) — 성 지하를 1인칭 격자 던전으로.
한 칸 전진이 1턴, 90도 회전이 1턴. 24×24 미로를 손으로 그렸다.

**▶ [열어보기](https://havergooday.github.io/darkforest/experiment/dungeon.html)**

숲과 달리 **벽이 있다.** 그래서 숲에서 겪은 문제 여럿이 애초에 생기지 않는다.

| 숲 | 던전 |
|---|---|
| 나무 사이로 다 보여 "미지"가 안 생김 | 모퉁이 너머가 진짜로 가려진다 |
| 원-원 충돌 · 반지름 튜닝 · 터널링 | 벽 검사 한 줄 |
| 시야를 좁히려면 광원 모델이 필요 | 벽이 공짜로 차폐를 준다 |
| 71%가 구별 안 되는 칸 | 방의 모양이 곧 정체성 |

빌보드 스프라이트가 아니라 **DDA 레이캐스팅**이다. 오브젝트 285개를 정렬하던
숲보다 오히려 싸다 — 1920×1080 에서 3ms (숲은 8~10ms).

아홉 개 방을 복도로 잇되 몇 군데를 막아 미로로 만들었다. 입구(S)와 계단(SE)
사이를 직접 잇지 않아 크게 돌아가야 한다. 방마다 내부가 다르다 — 감방, 기둥 홀,
무너진 방, 우물, 서고, 비문이 있는 막다른 방.

**생물**이 둘 돌아다닌다. 글자 행렬을 화면 크기에 맞춰 늘려 그리고, 좌우 흔들림·숨·
눈 깜빡임을 절차적으로 얹었다. 벽에 가려지며, 벽과 같은 색 계열이면 실루엣이 돌에
뭉개지므로 생물 전용 색을 쓴다.

| | 실루엣의 단서 | 속도 | 행동 |
|---|---|---|---|
| **쥐** | 위로 솟은 두 귀, 낮고 넓은 몸 | 0.5 (두 턴에 한 칸) | 쫓아온다. 시야가 끊기면 6턴 만에 놓친다 |
| **박쥐** | 양옆으로 뻗은 날개 | 0.9 | 쫓지 않고 어지럽게 난다 |

**속도가 1이면 절대 못 떨쳐낸다.** 회전도 턴이라 두리번거리는 사이에 붙기 때문이다.
쥐를 0.5로 두어 걸어서 벗어날 수 있게 했다.

작게 그려지면 세부는 다 사라지고 실루엣만 남는다. 그래서 **무엇인지 알아볼 단서를
실루엣에 넣어야 한다.** 그리고 한 점만 집어 줄이면 가는 것이 통째로 사라진다 —
실제로 눈이 없어졌다. 출력 칸이 덮는 원본 구간을 훑고 눈에 우선권을 준다.

문은 깨어난 생물도 연다. 플레이어만 열게 두면 문이 생물에게 넘을 수 없는 벽이 된다.

**손에 든 것**을 화면 아래 양쪽에 얹는다 — 왼쪽 등불, 오른쪽 검. 원근이 없으므로 z 판정도 거리 감쇠도
하지 않고, 늘 또렷하다. 걸을 때만 위상이 빨리 돌아 위아래로 흔들린다. 아래로 잘리면
형태가 사라져 벽처럼 보이므로 전체가 화면 안에 들어오게 잡았다.

**공격 모션**은 `Space`. 아스키 격자는 회전하지 않으므로 검을 돌리는 대신
**대각선 궤적을 따로 그려** 화면을 쓸고 지나가게 한다 — 회전 없이 "벴다"가 읽히는
가장 싼 방법이다. 들어올림 → 베기 → 회수의 세 구간을 진행도로 보간한다.

**등불**은 `Shift` 로 켜고 끈다. 꺼진 기본 시야가 6칸, 켜면 2.7배인 16칸이다 —
이 게임에서 불이 곧 볼 수 있는 거리라는 규칙을 손에 든 물건으로 옮긴 것이다.
불꽃은 켜져 있을 때만 밝게 흔들린다. (연료는 아직 없다. 넣으면 "불 = 탐험
예산"이 그대로 성립한다.)

> 기본 시야는 원래 16이었다. 그때는 어둠(4단계)이 12.8칸 밖부터라 5칸짜리 방이
> 통째로 최고 밝기였다 — **밝기 차이가 없으니 면도 갈리지 않아 화면이 뭉갰다.**
> 6으로 내리니 4.8칸 밖이 어둠이 되어 방 하나가 다 들어오지 않고, 같은 방 안에서도
> 가까운 벽과 먼 벽이 다른 단계로 그려진다. 어두워진 대신 형태는 더 잘 읽힌다.
> 값은 화면 위 슬라이더(3~30)로 실시간으로 바꿔 볼 수 있다.

**전투**가 들어갔다. 기획서가 배제하던 선을 넘은 것이므로 별도 결정이었다.

| | 체력 | 피해 |
|---|---|---|
| 플레이어 | 20 | 검 4 |
| 쥐 | 6 | 2 (붙으면 문다) |
| 박쥐 | 3 | 0 (물지 않는다) |

- 휘두르기는 한 턴. 맞은 쪽은 잠깐 움찔해 물러났다가 다시 다가온다
- 맞으면 화면이 흔들린다. 문자 격자에서는 통째로 밀기만 하면 되어 싸다
- 쓰러지면 입구에서 깨어난다. 지도도 잡은 것도 그대로다 — **되돌아가는 걸음이
  곧 대가다.** 게임 오버 화면은 두지 않았다

### 지도

지도는 밟은 칸만 남는다. 본편의 **종이 = 지도 기억**이 곁다리에서 게임의 중심이
되는 자리다.

**지도는 글자 흐름이 아니라 고정 격자다.** 처음엔 `white-space:pre` 로 글자를
흘렸는데, 좌우로 방향을 바꾸면 그 행이 통째로 밀려 격자가 깨져 보였다. 범인은
화살표였다 — `▶◀`(U+25B6/25C0)는 모노스페이스 폰트에서도 **한 칸 폭이 아니다.**
`▲▼` 와 폭이 달라 앞뒤 회전에서는 멀쩡하고 좌우에서만 깨진 것이다.

칸을 CSS 격자의 상자로 바꾸니 어떤 글자가 들어와도 흔들리지 않는다. 그래서
화살표는 그대로 두었다 — 고칠 대상은 글자가 아니라 **글자를 담는 방식**이었다.
덤이 둘 붙었다. 칸이 **정사각**이 되었고(예전 8.2 × 13.8px 는 평면도를 위아래로
늘려 놨다), 벽을 글자 대신 **칸 배경**으로 칠할 수 있게 되어 줄 사이 틈 없이
이어진다. 성이 평면도로 읽힌다.

| 칸 | 표시 |
|---|---|
| 벽 | 채운 칸 |
| 밟은 바닥 | `·` 밝게 |
| 곁눈으로 본 바닥 | `·` 어둡게 |
| 문 | `+` 황토색 |
| 지형지물 | `< > ! o ~` 주황 |
| 생물 | `r` `b` 붉게 |
| 나 | `▶▼◀▲` |

> **DOM 이 곧 비용이다.** 576칸을 프레임마다 다시 그리면 안 된다. 칸은 한 번만
> 만들고, 매 프레임 **달라진 칸만** 고쳐 쓴다 — 회전 한 번에 DOM 쓰기 2회다
> (전부 다시 그리면 1152회). 그 앞에 서명 비교를 하나 더 둬서, 지도가 안 바뀐
> 프레임은 576칸을 훑지도 않는다. 0.461ms → 0.002ms.

> **밟은 칸과 곁눈질한 칸을 나누면서 묵은 버그가 드러났다.** `mark()` 가
> `if(!visited[k])` 로 걸러 밟은 칸을 1 로 올렸는데, 앞 칸은 **늘 곁눈질로 먼저
> 2 가 된다.** 그래서 그 위에 올라서도 1 이 되지 못했다 — HUD 의 "밟은 칸"이
> 시작 이후 영영 1 이었고, 지형지물 발견 알림도 시작 칸 말고는 뜨지 않았다.
> 지도가 두 상태를 구분해 그리기 전까지는 아무도 눈치채지 못했다.

### 내려가는 계단 — 세 번 만에

계단은 원래 `=` 로 꽉 채운 사각 판때기였다. 상자를 한 글자로 칠할 뿐이라 형태가
아예 없었다. 고치는 데 세 번 걸렸고, 앞의 두 번은 각각 다른 이유로 틀렸다.

**1. 바닥 평면에 새기기.** 내려가는 계단은 바닥에 뚫린 구멍이니 세운 판이 아니라
바닥에 그리는 게 옳아 보였다. 바닥 캐스팅이 이미 칸 안의 위치를 알고 있어 원근도
공짜였다. 그런데 화면 가로:세로가 3:1 이라 **수직 화각이 33도뿐**이고, 그래서
바닥 평면은 **2.3칸보다 먼 것만** 담는다. 결과가 정반대였다 — 다가갈수록 사라진다.

**2. 빌보드에 그림 넣기.** 다가갈수록 커지긴 했다. 그런데 바닥에 세운 카드라
여전히 "구멍"이 아니라 "판때기"로 읽혔다.

**3. 벽에 붙이기.** 성의 계단은 방 한가운데 뚫려 있지 않다 — 벽에 난 아치
안으로 내려간다. 벽 장식 렌더러는 이미 벽면 좌표(u·v)에 그리므로 원근이 정확하고,
다가가면 벽과 함께 커진다. 앞의 두 문제가 한꺼번에 없어졌다.

| 거리 | 바닥 평면 | 빌보드 | 벽 아치 |
|---|---|---|---|
| 3칸 | 28칸 | — | 49칸 |
| 2칸 | 27칸 | 54칸 | 114칸 |
| 1칸 | **0칸** | 199칸 | **208칸** |

바닥 타일 `>` 는 그림을 갖지 않는다. **"여기 서라"는 표시**로만 남아 지도에 찍히고
HUD 에 이름을 준다. 그래서 계단 칸을 벽 앞으로 옮겼다 — (19,19) 방 한가운데에서
(19,21) 동쪽 벽 앞으로.

> **공백은 어둠이 아니다.** 벽 장식에서 공백은 투명이라 벽이 비쳐 보인다. 구멍을
> 그리려면 어둠을 따로 칠해야 해서 `V` 를 두었다. 2칸 앞에서 계단이 벽에 뚫어
> 놓는 빈칸이 27개다.

> 그 벽면에는 원래 횃불이 있었다. 같은 키라 조용히 밀려나므로 같은 방 남쪽 벽으로
> 옮겼다. 벽면 하나에 장식 하나 — 덮어쓰기를 막는 장치는 없다.

### 두 층

지하 1층은 3×3 방 격자, 지하 2층은 좁은 통로가 얽힌 묘소다. 층마다 지도·장식·문·
생물·발자국을 따로 지니고, `useFloor()` 하나만 갈아 끼우면 나머지 코드는 지금 층만
본다. 두 계단이 서로를 마주 보므로 **내려갔다 올라오면 정확히 같은 자리**다.

| | 1층 | 2층 |
|---|---|---|
| 통행칸 | 268 | 204 |
| 문 | 8 | 7 |
| 벽 장식 | 9 | 9 |
| 생물 | 박쥐 1 · 쥐 1 | 쥐 2 · 박쥐 1 |

> **좌표는 손으로 세면 틀린다.** 2층 장식을 손으로 놓았더니 아홉 중 넷이 벽이 아닌
> 칸에 붙었다. 벽면이고, 볼 자리가 있고, 두 칸 물러설 여지가 있는 곳을 **코드로 골라**
> 다시 놓았다. 계단 타일도 아치 벽과 한 칸 떨어져 있어 아치가 아예 안 보였다.

> **도착하면 계단을 등진다.** 방위를 늘 동쪽으로 박아 뒀더니, 올라온 직후 방금 올라온
> 계단을 정면으로 보고 서 있었다 — "되돌아가라"로 읽힌다. 도착한 칸 둘레에서 아치를
> 찾아 그 반대쪽을 본다. 장식 면(0북 1동 2남 3서)을 방위(0동 1남 2서 3북)로 옮기는
> 표 하나면 된다.

### 계단 연출 — 창살 너머의 한 장면

`Enter` 또는 **계단 이용** 버튼. 6초짜리 장면이 끼어든다. 나중에 층을 생성하고
저장할 시간을 벌 자리이기도 하다.

전체 암전에서 시작해, 어둠 속에 그리스식 기둥이 서 있고 **작은 불빛 하나가 계단을
따라 지나간다.** 내려갈 때는 왼쪽 위에서 오른쪽 아래로, 올라갈 때는 그 반대로.
기둥이 불빛을 가리므로 지날 때마다 가려졌다 드러난다. 다시 암전.

`render` 와 무관하게 격자를 새로 짠다 — 미로 렌더러를 건드리지 않는다.

- **바닥**은 `1/깊이` 로 눕는다. 미로의 바닥 캐스팅과 같은 관계다. 그래서 같은
  크기의 빛무리라도 가까울수록 넓게 퍼지고 멀수록 오므라든다
- **계단**은 열마다 지평선을 한 단씩 내려 만든다. 원근을 따로 손대지 않아도 된다.
  한 단 높이 대신 **시작·끝 높이를 화면 비율로** 못 박아, 보고 싶은 대로 맞춘다
- **불빛**은 기둥보다 깊이가 커야 가려진다. 앞으로 나오면 아무것도 가리지 못한다
- **기둥**은 위아래로 꽉 차고 차가운 돌색이다. 빛이 번진 모서리만 따뜻하다 —
  그 갈림이 "따뜻한 장면을 차가운 창살 너머로 본다"를 만든다

> **암전이 한쪽만 됐다.** `dark>=4` 로 걸었더니 `(1-0.98)/0.16` 이 부동소수점 탓에
> 3.4999… 가 되어 3 으로 내려앉았다. 시작 쪽은 정확히 0.125 라 4 가 된다. 밝기로
> 바로 거르니 양쪽이 같아졌다.

> **맞추는 곳과 쓰는 곳을 나눴다.** 숫자를 눈으로 맞추려면 매번 게임을 켜야 하는데,
> 그러면 던전과 연출을 동시에 고치게 되어 어긋난다. 슬라이더가 달린 작업대
> [`experiment/cine.html`](experiment/cine.html) 에서 맞추고, 정해진 값만 옮긴다.

> **DOM 이 곧 비용이다.** 작업대는 매 프레임 화면 전체를 `innerHTML` 로 갈아끼워
> 초당 요소 4만 개를 버리고 새로 만들었고, 브라우저가 눈에 띄게 느려졌다.
> 계산 시간(3ms)만 재고 DOM 을 안 잰 탓이다 — 예전에 브라우저를 터뜨렸던 그
> 함정이다. **달라진 행만** 고쳐 쓰고 30fps 로 낮추고 안 보이는 창에서는 그리지
> 않으니 초당 4,890 개로 줄었다(87% 감소).

**벽면은 민무늬다.** 돌 무늬(가로 층·세로 줄눈)를 넣어 봤더니 화면이 어지러워서
걷어냈다. 형태를 읽히게 하는 건 결이 아니라 **면을 가르는 선**이었다.

**무늬와 장식은 다르다.** 무늬는 모든 벽에 반복되므로 정보가 없으면서 눈만
어지럽힌다. 장식은 특정 벽면에만 붙으므로 똑같은 벽 사이에서 **랜드마크**가 된다 —
"횃불 있던 벽"이 기억의 닻이 되어 길찾기를 돕는다. 그래서 성기게 둔다.

**횃불만 둔다.** 쇠창살·사슬·해골도 만들어 봤지만 던전의 톤과 안 맞았고, 균열은
비밀벽처럼 읽혀 오해를 낳았다. 층마다 아홉 개 — 횃불과 계단 아치뿐이다.

문과 같은 방식으로 벽면 좌표(u·v)에 상자를 잡아 그린다. 멀면 잡티가 되므로
가까울 때만 그린다. 불꽃은 명멸한다.

> 배치에는 제약이 있다. **횃불은 불꽃이 위쪽에 있어 두 칸 이상 물러설 수 있는 벽에만
> 걸 수 있다.** 기둥 사이처럼 볼 자리가 코앞 한 칸뿐이면 불꽃이 화면 위로 잘린다.

- **모서리 이음매** — 이웃 열과 보고 있는 면이 다르면 그 자리를 어둡게 갈라 준다.
  두 벽이 한 덩어리로 뭉쳐 보이지 않게 하는 것이 형태 인지에 가장 크게 기여한다
- **남북/동서의 밝기 차이** — 방향광처럼 읽혀 면이 갈린다
- **실루엣** — 벽이 바닥과 만나는 줄을 밝게

바닥과 천장에 **칸 경계선을 대칭으로** 긋는다. 선이 위아래에서 소실점으로 모이는
것이 깊이를 알려주는 가장 큰 단서다 — 천장을 비워 두었더니 단서가 절반뿐이라
공간이 얕아 보였다.

**공간 비율.** `WALLH` 는 "칸 폭 1 에 대해 벽이 얼마나 높은가" 를 정한다.

```
rows = H*WALLH/d 이고 화면 비를 W ≈ 3H 로 고정했으므로
세로 화각 vFOV = FOV/1.8, 따라서 벽의 실제 높이 = WALLH * FOV / 1.8
```

1.55 였을 때 실제 높이가 **0.90 유닛** — 폭 1.0 짜리 복도에 천장이 0.90 이라
기어다니는 굴 비율이었다. 그래서 모든 것이 얼굴에 붙어 보였다. 2.10 으로 올려
1.22 로 만들었다.

가로 화각을 넓히는 것은 반대 방향이었다. 넓히면 0.5 유닛 앞의 옆벽이 화면을
더 먹어 오히려 더 답답해진다.

**바닥에 놓인 것은 바짝 붙으면 발밑으로 밀려난다.** 한 칸 앞의 쥐가 실제로 6% 만
보였다 — 안 보이는 것과 싸운 셈이다. 계단은 옆에 서면 아예 사라졌다. 사람이라면
고개를 숙여 볼 것이므로 아래로 삐져나가는 양을 제한한다(`frameBase`). 멀리 있을
때는 걸리지 않아 바닥에 붙은 채로 남는다. 쥐 74%, 계단 75% 로 회복.

떠 있는 것(박쥐)은 이 문제가 없었다. 그래서 박쥐만 멀쩡해 보였던 것이다.

**다만 붙잡고만 있으면 지나칠 때가 어색해진다.** 발밑으로 흘러가지 못하고 화면에
걸린 채 커지다가 툭 사라진다 — 실제로 한 칸 앞에서 108칸이던 것이 반 칸 앞에서
330칸으로 부풀었다가 그대로 없어졌다. 그래서 `frameBase` 는 거리에 따라 놓아 준다.
한두 칸 앞이면 붙잡고, 바짝 붙으면 흘려 보낸다.

거기에 두 가지를 더했다. 크기에 하한 거리(`NEAR_MIN`)를 두어 `1/d` 가 폭주하지
않게 하고, 각도 컷을 화면 밖으로 밀어 화면 안에서 잘려 사라지지 않게 했다.
이제 한 칸 앞에서 최대가 되고 그 뒤로는 아래로 빠져나간다.

**문은 다가가면 열린다.** 인접한 칸에 서면 문짝이 한쪽으로 밀려 들어가고,
그제야 광선이 통과해 **너머가 보인다.** 열려도 인방(문 위 돌)은 남으므로 통로로
읽힌다. 문이 시야를 막는다는 것이 곧 "열기 전에는 모른다"가 된다.

### 숲 (1인칭)

[`experiment/first-person.html`](experiment/first-person.html) — 본편의 7×7 지도를 1인칭 아스키로
그려본 것. 게임 로직은 없고 걸어보기만 된다. 본편과 별개이며 채택 여부는 미정.

**▶ [열어보기](https://havergooday.github.io/darkforest/experiment/first-person.html)**

벽 기반 레이캐스팅이 아니라 나무를 거리순으로 세우는 빌보드 스프라이트 방식이다.
숲은 벽이 아니라 개방 공간이므로 이쪽이 간단하고 숲처럼 보인다. 깊이는 문자 밀도
(`█▓▒░·`)로, 바닥 질감은 월드 좌표 해시로 낸다.

격자 턴제와 자유 이동을 모두 넣어 감각을 비교할 수 있다. 이 선택이 중요한 이유는
**"행동 하나가 1턴"이 본편의 뼈대**이기 때문이다. 자유 이동을 택하면 체온·허기·불
소모가 전부 시간 기반으로 바뀌고 밸런싱을 다시 잡아야 한다.

**야영지 (3,5) 를 손으로 배치했다.** 거점에서 동쪽으로 보면 나무 위로 솟은 것이 보이고,
다가가면 형태가 드러나고, 네 단계로 텍스트가 붙는다. 게임 로직 없이 **발견의 질감만**
확인하기 위한 것 — 다가가는 것이 재미있는가(탐험) / 무서운가(공포) / 그냥 상자인가(생존).

**충돌**은 이동 선분과 원의 교차를 직접 푸는 스윕 방식이다. 접촉 직전에서
**멈춘다** — 미끄러지지 않는다. 부딪히면 서야 벽으로 읽힌다.

최종 위치만 검사하는 밀어내기 방식을 먼저 썼다가 두 가지가 드러났다. 하나는
한 프레임(최대 0.35유닛)에 나무를 통째로 건너뛰어 **반대편에서 밀려나는** 것 —
"나무를 지나고 나서 멈추는" 느낌의 원인이다. 다른 하나는 표면을 따라 흘러가
부딪힌 느낌이 나지 않는 것. 스윕은 둘 다 해결한다.

충돌 반지름은 **렌더 기하에서 유도한다.** 손으로 정했더니 실제로 보이는 크기의
5~18배로 벌어져, 나무에서 한참 떨어진 곳에서 멈췄다. 격자 턴제는 칸 중심을 잇는
십자선을 따라 이동하므로, 그 선에서 **종류별 반지름만큼 비켜난 곳에만** 나무를
배치해 이동이 절대 막히지 않게 했다. 결과적으로 나무가 네 귀퉁이에 모이고
그 사이로 길이 난다.

불빛 슬라이더로 가시거리를 조절할 수 있다. 이 게임에서 불은 이미 체온이자 시간
(나뭇가지 총량 = 탐험 예산)인데, 1인칭에서는 시야까지 겸할 수 있다.

### 계단 연출 작업대

[`experiment/cine.html`](experiment/cine.html) — 계단 연출만 반복 재생하며
슬라이더로 숫자를 맞추는 곳이다. 기둥 수·두께·깊이·홈, 불빛 크기·깊이·높이,
바닥 기울기, 계단 수와 시작·끝 높이, 한 판 시간.

쓰는 곳을 나누고**, 정해진 값만 던전으로 옮긴다.
