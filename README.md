# 숲 (darkforest)

숲 한가운데서 눈을 뜬다. 가진 건 아무것도 없다.
불을 피우고, 자원을 모으고, 도구를 만들며 며칠을 버틴다.

**▶ [플레이](https://havergooday.github.io/darkforest/)**

브라우저에서 도는 텍스트 서바이벌. 단일 HTML 파일이고 빌드·의존성·서버가 없다.
진행 상황은 브라우저 `localStorage`에 자동 저장된다.

## 핵심 루프

```
탐색 → 채집 → 거점 복귀 → 제작 → 더 멀리 탐색
                  ↑
              불 / 체온 회복
```

행동 하나가 1턴. 턴이 지나면 허기와 체온이 깎이고, 거점의 불 옆에서만 체온이 회복된다.

- **허기**는 생존, **체온**은 능력 — 역할이 겹치지 않는다. 어느 쪽을 먼저 해결할지 매 순간 고른다
- 거점에서 멀수록 체온이 빨리 깎이고, 대신 칸의 자원 잔량이 많다
- 칸은 다 캐면 마른다. 소지 한도가 있으니 여러 칸을 돌아야 한다
- 열매로는 못 버틴다. 도구를 만들어 사냥으로 넘어가야 살아남는다

## 조작

- **이동** — 지도에서 인접한 칸 클릭, 또는 방향키 / `WASD`
- **행동** — 오른쪽 목록에서 선택
- 지도 아래 범례와 로그가 현재 상황을 알려준다

## 로컬에서 열기

```sh
python -m http.server 8765 --bind 127.0.0.1
# http://127.0.0.1:8765/
```

`file://`로 직접 열어도 돌아가지만, 브라우저마다 `file://` origin의 `localStorage` 취급이
달라 저장·불러오기 동작이 어긋날 수 있다.

## 개발용 콘솔

브라우저 콘솔(F12)에서 `game.help()`

```js
game.s                       // 상태 전체
game.skip(20)                // 20턴 넘기기
game.give('stone', 20)       // 자원 지급
game.all()                   // 자원 + 제작대 2단계
game.tool()                  // 도구 전부 해금
game.keep()                  // 소지품 전부 획득
game.reveal()                // 지도 공개
game.tune({TEMP_FIRE: 20})   // 새로고침 없이 밸런싱 값 변경
game.reset()                 // 새로 시작
```

밸런싱 수치는 `index.html` 상단 `CONFIG` 블록에 모여 있다.

## 테스트

```sh
node test/all.js
```

Node만 있으면 된다. 게임 자체에는 의존성이 없고, 테스트도 외부 패키지를 쓰지 않는다.

`index.html`의 `<script>` 블록을 그대로 꺼내 `vm` 컨텍스트에서 돌리고, `document`와
`localStorage`만 최소 스텁으로 채운다. 미리 추출한 사본을 두지 않으므로 **항상 실제로
배포되는 파일을 검증한다.**

| 스위트 | 검증 대상 |
|---|---|
| `test/bugfix.test.js` | 재료 검사, 빈 칸 채집, 세이브 스키마 복원 |
| `test/loot.test.js` | 야영지 발견물, 소지 한도 부분 획득, 잔존·재방문 |
| `test/keep.test.js` | 소지품 가방, 구버전 세이브 이관, 확장성 |

주로 **조용히 상태를 깨뜨리는 종류**를 잡는다 — 재료 없이 제작대가 세워져 가방 수량이
음수가 되는 것처럼, 화면상으로는 정상이라 눈으로는 알 수 없는 버그다.

## 실험

### 던전 (위저드리식)

[`experiment/dungeon.html`](experiment/dungeon.html) — 성 지하를 1인칭 격자 던전으로.
한 칸 전진이 1턴, 90도 회전이 1턴. 24×24 미로를 손으로 그렸다.

**▶ [열어보기](https://havergooday.github.io/darkforest/experiment/dungeon.html)**

숲과 달리 **벽이 있다.** 그래서 숲에서 겪은 문제 여럿이 애초에 생기지 않는다.

| 숲 | 던전 |
|---|---|
| 나무 사이로 다 보여 "미지"가 안 생김 | 모퉁이 너머가 진짜로 가려진다 |
| 원-원 충돌 · 반지름 튜닝 · 터널링 | 벽 검사 한 줄 |
| 시야를 좁히려면 광원 모델이 필요 | 벽이 공짜로 차폐를 준다 |
| 71%가 구별 안 되는 칸 | 방의 모양이 곧 정체성 |

빌보드 스프라이트가 아니라 **DDA 레이캐스팅**이다. 오브젝트 285개를 정렬하던
숲보다 오히려 싸다 — 1920×1080 에서 3ms (숲은 8~10ms).

아홉 개 방을 복도로 잇되 몇 군데를 막아 미로로 만들었다. 입구(S)와 계단(SE)
사이를 직접 잇지 않아 크게 돌아가야 한다. 방마다 내부가 다르다 — 감방, 기둥 홀,
무너진 방, 우물, 서고, 비문이 있는 막다른 방.

**몬스터**가 하나 돌아다닌다. 글자 행렬(11×14)을 화면 크기에 맞춰 최근접 표본으로
늘려 그리고, 좌우 흔들림·숨·눈 깜빡임을 절차적으로 얹었다. 벽에 가려지고, 플레이어가
턴을 쓸 때마다 한 칸 다가온다. 전투는 없다 — 존재만으로 압박을 준다.
벽과 같은 색 계열이면 실루엣이 돌에 뭉개지므로 몬스터 전용 색을 쓴다.

지도는 밟은 칸만 남는다. 본편의 **종이 = 지도 기억**이 곁다리에서 게임의 중심이
되는 자리다.

**벽면은 민무늬다.** 돌 무늬(가로 층·세로 줄눈)를 넣어 봤더니 화면이 어지러워서
걷어냈다. 형태를 읽히게 하는 건 결이 아니라 **면을 가르는 선**이었다.

- **모서리 이음매** — 이웃 열과 보고 있는 면이 다르면 그 자리를 어둡게 갈라 준다.
  두 벽이 한 덩어리로 뭉쳐 보이지 않게 하는 것이 형태 인지에 가장 크게 기여한다
- **남북/동서의 밝기 차이** — 방향광처럼 읽혀 면이 갈린다
- **실루엣** — 벽이 바닥과 만나는 줄을 밝게

천장은 비웠고, 바닥에는 칸 경계선만 그었다. 격자가 눈에 보여야 지도가 읽힌다.

**문은 다가가면 열린다.** 인접한 칸에 서면 문짝이 한쪽으로 밀려 들어가고,
그제야 광선이 통과해 **너머가 보인다.** 열려도 인방(문 위 돌)은 남으므로 통로로
읽힌다. 문이 시야를 막는다는 것이 곧 "열기 전에는 모른다"가 된다.

### 숲 (1인칭)

[`experiment/first-person.html`](experiment/first-person.html) — 본편의 7×7 지도를 1인칭 아스키로
그려본 것. 게임 로직은 없고 걸어보기만 된다. 본편과 별개이며 채택 여부는 미정.

**▶ [열어보기](https://havergooday.github.io/darkforest/experiment/first-person.html)**

벽 기반 레이캐스팅이 아니라 나무를 거리순으로 세우는 빌보드 스프라이트 방식이다.
숲은 벽이 아니라 개방 공간이므로 이쪽이 간단하고 숲처럼 보인다. 깊이는 문자 밀도
(`█▓▒░·`)로, 바닥 질감은 월드 좌표 해시로 낸다.

격자 턴제와 자유 이동을 모두 넣어 감각을 비교할 수 있다. 이 선택이 중요한 이유는
**"행동 하나가 1턴"이 본편의 뼈대**이기 때문이다. 자유 이동을 택하면 체온·허기·불
소모가 전부 시간 기반으로 바뀌고 밸런싱을 다시 잡아야 한다.

**야영지 (3,5) 를 손으로 배치했다.** 거점에서 동쪽으로 보면 나무 위로 솟은 것이 보이고,
다가가면 형태가 드러나고, 네 단계로 텍스트가 붙는다. 게임 로직 없이 **발견의 질감만**
확인하기 위한 것 — 다가가는 것이 재미있는가(탐험) / 무서운가(공포) / 그냥 상자인가(생존).

**충돌**은 이동 선분과 원의 교차를 직접 푸는 스윕 방식이다. 접촉 직전에서
**멈춘다** — 미끄러지지 않는다. 부딪히면 서야 벽으로 읽힌다.

최종 위치만 검사하는 밀어내기 방식을 먼저 썼다가 두 가지가 드러났다. 하나는
한 프레임(최대 0.35유닛)에 나무를 통째로 건너뛰어 **반대편에서 밀려나는** 것 —
"나무를 지나고 나서 멈추는" 느낌의 원인이다. 다른 하나는 표면을 따라 흘러가
부딪힌 느낌이 나지 않는 것. 스윕은 둘 다 해결한다.

충돌 반지름은 **렌더 기하에서 유도한다.** 손으로 정했더니 실제로 보이는 크기의
5~18배로 벌어져, 나무에서 한참 떨어진 곳에서 멈췄다. 격자 턴제는 칸 중심을 잇는
십자선을 따라 이동하므로, 그 선에서 **종류별 반지름만큼 비켜난 곳에만** 나무를
배치해 이동이 절대 막히지 않게 했다. 결과적으로 나무가 네 귀퉁이에 모이고
그 사이로 길이 난다.

불빛 슬라이더로 가시거리를 조절할 수 있다. 이 게임에서 불은 이미 체온이자 시간
(나뭇가지 총량 = 탐험 예산)인데, 1인칭에서는 시야까지 겸할 수 있다.
